## Decisions (for FORK.md "Decisions taken while building")

| Decision | Reason | Date |
|---|---|---|
| The closed set is enforced in `packages/adapters`, not only in `apps/api/src/me/gfin/` | The brief's paths are targets; the worker process runs agent tool calls and cannot import the API app, so the enforcement point both processes share is the adapter package (which the repo's own rules allow to carry vendor-specific configuration). The provisioning service stayed in `apps/api/src/me/gfin/`. | 2026-11-17 |
| The guard matches the connection by server slug `gfin` (`route.catalogGroup`) | Tool routes carry the slug; no schema change or registry patch is needed. A person who names their own server exactly `gfin` would also be restricted to the closed set; accepted and documented, the slug is the contract the portal module (`apps/web/src/me/gfin.tsx`, packet I) already reads. | 2026-11-17 |
| The key is stored as MCP credential material (`{ secret }`), not headers | The connector already normalises a static `secret` to `Authorization: Bearer ...` at connect time, so the material needs no second rule and the row keeps only key-presence maps. | 2026-11-17 |
| An unreachable provisioning endpoint degrades, named, to the public-search connection; a malformed response never does | Unreachable is the named degraded path the brief already runs; a malformed `gfin_` key means the contract broke, so it is a named refusal (`GfinKeyMalformedError`, `gfin_key_malformed`) with no row written and no silent fallback to the house key. The next admission retries. | 2026-11-17 |
| Convergence runs at every workspace admission, not only account creation | One code path serves creation, the automatic switch to the personal key, and healing of accounts created before this code (the owner's included); the steady-state cost is one indexed `findFirst`. When the connection is already personal the path stays off the network. | 2026-11-17 |
| The connection is created `allSpaces`/`allBots` like a server the person added themselves | Every agent the person owns, in every space, sees the connection with no setup; the closed set comes from the guard, not from per-bot assignments. | 2026-11-17 |

## Tests

`packages/adapters/src/gfin-connection.test.ts` (vitest, offline, 8 tests, all pass) against a
stub MCP server that speaks JSON-RPC through stubbed fetch (no real network):
1. `tools/list` through the guard returns exactly the closed set (`mcp__gfin__search_opportunities`,
   `mcp__gfin__get_opportunity`) while the stub server offers four tools.
2. Other MCP servers pass through untouched (their tools are not filtered).
3. A tool outside the closed set is refused with `gfin_tool_not_allowed` and the stub server
   received zero requests, not even a session initialisation.
4. An `org_id` argument, top level or nested, is refused with `gfin_org_id_refused` before any
   request (the stub received zero requests).
5. An allowed call without `org_id` passes through to the stub server and returns its result.
6. A refusal is logged with the tool name and reason code only: the log line contains neither
   the argument values nor the argument keys.
7. Unit: `findBlockedArgKey` finds the key at depth, misses on clean arguments;
   `guardedToolRefusal` refuses an unknown tool and a blocked key.
8. `parseGfinConnectionEnv` reads the deployment config; each provisioning value alone fails
   the boot, the pair parses, and no GFIN config at all returns undefined.

`apps/api/src/me/gfin/service.test.ts` (vitest, offline, 7 tests, all pass) against an
in-memory Prisma double and the real encrypted secret store:
1. On account creation the connection is created with no user action: row named "Go Fund It Now
   (public search)", slug `gfin`, the deployment endpoint, `allSpaces`/`allBots`, one `secrets`
   row of kind `mcp` whose ciphertext decrypts to `{ secret: <house key> }`.
2. The key appears in no row JSON, no returned object, and no other surface: the joined sweep
   of every row serialisation and the outcome object does not contain the key (the ciphertext
   does not contain it recognisably either).
3. A second admission converges: no second row, no second secret, `current`.
4. No `ME_GFIN_*` config: named `off`, no row.
5. With the provisioning endpoint configured, the personal key is used and the label becomes
   "Go Fund It Now"; the request carries `Authorization: Bearer <service token>` and the body
   names the person (`userId`, `email`) and carries no `org_id`.
6. An existing public-search connection is re-keyed to the personal key automatically: the
   label changes, the secret row is swapped, the old secret row is deleted, one revision up.
7. A malformed per-person key (no `gfin_` prefix) is refused by name
   (`GfinKeyMalformedError`, `gfin_key_malformed`), with no row and no fallback to the house
   key; an unreachable endpoint (HTTP 503) degrades, named, to the public-search connection.

## Unverified

- No live GFIN call has been made: the house key is an owner step (W0.3 / O5), and until it is
  in the deployment env, provisioning logs `gfin connection provisioning is off` once at boot
  and no connection is created. The stub server stands in for `app.gofunditnow.com/api/mcp`.
- The G3 contract is written from the fork side only: request `{ userId, email }` with a Bearer
  service token, response `{ key: "gfin_..." }`. Settling the request body with packet E2
  (linking by verified phone, whose proof the fork holds only as a hash) is still open; the
  seam re-resolves on the next admission, so a contract adjustment is a local change.
- The migration has not run against a real database here; it is one plain concurrent index
  build on `mcp_servers` and runs at the next deploy with the previous release still live.
- Lazy catalog mode (more than 20 MCP tools across a run's assignments) would present GFIN
  tools as catalog entries; `resolveCall` refuses them before execution and `execute` refuses
  them before any request, but the model may still see the entry names in that mode. The demo
  deployment is far below the limit.
- The portal surfaces reading the connection (packet I's `apps/web/src/me/gfin.tsx`) were being
  written by another session in the same checkout while this packet ran; the shared contract is
  the slug `gfin` and the row's `name`, both owned here.
